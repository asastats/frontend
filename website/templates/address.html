The `sr-only` label is a sibling for that reason; the data attributes ride on the span itself, because `address.js` reads them off `$(".pricetip")[0]`. **The `.tooltip` is a wrapper and the focusable element is the span inside it.** DaisyUI reveals a tooltip on `:has(:focus-visible)` - a focused *descendant* - so a tabindex on the `.tooltip` element matches nothing and draws nothing. This is the one figure whose tooltip carries something available nowhere else, the exchange rate, which is why it is a tab stop and the others are not. The `sr-only` span is what a screen reader gets, because a tip drawn as `content: attr(data-tip)` is not dependably announced; `setTip` keeps the two in step. {% endcomment %} {% comment %} **`data-totalnftfloor` and `data-holdings` sit on the h1**: the live refresh replaces the span below whole, so an attribute inside it is gone after the first update.
