{% comment %} The money-column toolbar: pass 2 of designs 2 and 3. Everything here acts on the page already in the browser. Nothing fetches: the whole payload is in the DOM, sort keys and categories rendered onto the rows as data attributes (see `snippets/money/asset.html` and `position.html`), so filtering 190 positions is a class toggle rather than a round trip. That is also why the state is the reader's and lives in their browser -- this page's cache entry is shared by everyone on the layout, so the server cannot know any of it and must not render any of it. **Every control ships in its default state**, for the same reason. The reader's actual state is applied by `toolbar.js` on load. A control rendered pressed because *someone* pressed it would be handed to whoever asked next. Two things are deliberately not here: * **A Rows/Cards toggle.** The prototype has one; here that choice is the layout the reader picked on the settings page -- `money-column` against `money-column-compact` -- which is a server-side preference and part of the cache key. A second, client-side control for the same thing would let the two disagree about which design the reader is looking at. * **Dismissing an asset.** The prototype's fifth header cell is a dismiss control; that feature is not built, so `reset` has nothing to undo for it. `role="search"` on the field's form landmark and `aria-pressed` on every segmented button: these are toggles, not links, and a screen reader is told which one is on. The counts beside the sort buttons are filled in by `toolbar.js` -- rendering them would be rendering the reader's filter. {% endcomment %} {% comment %} `data-floor` carries `ADDRESS_SECTION_FLOOR` to the browser so the two implementations of the load-more rule cannot drift. `utils/cutoff.py` never hides a section down to fewer rows than this -- a threshold alone would leave a wallet holding one large asset and eight small ones showing a single row, which is a fold that costs more than it saves. The toolbar re-cuts the same list against filtered values and has to honour the same floor. {% endcomment %}
