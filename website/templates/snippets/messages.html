{% comment %} Every Django message, rendered once for the whole site. Before this, nine templates each rendered `messages` themselves and no two agreed. Six of them used a bare `alert` with no tag branch at all, so a failure and a success were the same neutral box; `export.html` put Django's tag straight into `class` -- `class="success"`, which is not a DaisyUI class -- and rendered plain unstyled list items. `base.html` rendered none, which is why each page had to. **Errors stay on the page. Everything else is a dismissable toast.** An error is usually long, sometimes carries `mark_safe` markup, and is the reason the submit did not work -- it has to stay put and be re-readable. A "saved!" does not. `warning` and `debug` are not used anywhere in the project today; both fall to the toast branch. If a warning is ever added and it means "this did not fully work", move it up to the inline branch with the errors. The toast markup is rendered server-side rather than built in JavaScript, so a message is still readable with scripting off -- only dismissal and the auto-hide need `site.js`. {% endcomment %} {% if messages %} {% for message in messages %}{% if "error" in message.tags %}
