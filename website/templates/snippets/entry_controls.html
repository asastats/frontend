{% comment %} The two controls on an asset or collection row: reorder, and pin. Both are arrangement, both are remembered per address/bundle in the reader's own browser, and neither ever reaches the server -- see `static/js/pins.js`. That is not a shortcut: this page's cache entry is shared between signed-in readers, so anything per-reader rendered into it would be handed to whoever asked next. Rendering both in their *resting* state for everybody and letting the script set them is what keeps the markup shareable. `data-drag` and `data-pin` both carry the id of the entry they act on -- the same id `checkOpened` and the filter use, so an arrangement survives everything else that addresses the row. The grip comes first: it is the thing a reader reaches for when they want to move a row, and putting the destructive-looking pin under the cursor's resting position invites the wrong click. Required context: entry_id the entry's id *without* the `f` prefix (an asset id, or a slugified collection name) entry_label what to name in the accessible labels, e.g. the unit or the collection name {% endcomment %}
