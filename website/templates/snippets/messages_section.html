{% comment %} Toasts for one htmx-swapped section. `base.html` renders every message once, which is right for a full page load and wrong for these three. The settings forms post with htmx and carry `hx-select="#id-section-"`, so htmx keeps that fragment of the response and discards everything else -- including the toast container in `base.html`. The message is created, rendered into a part of the response nobody keeps, and consumed. It is never seen. That is why these confirmations were rendered inside their own sections before, filtered on `extra_tags`, and why centralising them silently broke the settings page. Restored here, as toast markup rather than the inline alert they used to be, so a reader gets the same thing whichever form they submit. `snippets/messages.html` skips these same three tags, so a full page load renders them here and not twice.
